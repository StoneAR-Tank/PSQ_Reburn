# 变身肤色保存与刷新修订

上一轮只修补了同步函数，颜色确认仍通过通用换装操作锁；变身流程或模型刷新占用时可能在保存之前退出。旧离线用例没有实际覆盖这条拦截路径。现在为肤色、发色、肤色强度和肤色开关分别增加SkyUI状态回调，先保存配置，再请求安全刷新。正常形态与变身形态均可保存，忙碌不会丢弃颜色配置。

颜色刷新使用独立事件并在关闭菜单后执行；请求编号合并连续设置，旧请求、旧读档回调和外来发送者不能写入。短暂模型忙碌最多重试10次，仍不可用就显示中文原因。正常形态仅保存；未启用变色时明确提醒开启选项。颜色专用锁不增加外观操作编号、不调用装备替换、不取消变身属性补满任务。

独立变身效果脚本原本会调用肤色应用，但之后还会更换头发、装备并重建节点。现在在外观操作完成后再请求一次颜色刷新，使刷新落在模型重建后；颜色刷新自身完成不会递归排队。不修改该独立效果脚本和任何外部模组。

Game.SetTintMaskColor后回读实际染色层，写入不匹配返回失败且保留原色备份。种族保护、缺少染色层、缺少模型、写入失败和恢复失败均使用直接中文通知，避免通知接口不能解析SkyUI翻译键而无可读说明。肤色仍只作用于现有染色层，不强制更换独立种族身体资源。

旧SexLab与P+2.19编译通过，最终字节码一致。134项实际最终字节码离线分支检查通过，覆盖变身与正常形态、换装忙碌时保存、菜单关闭后应用、原色恢复、透明度、种族保护、染色层缺失、原生写入不生效、过期请求、读档取消和颜色专用锁保留属性补满任务。504个其他主脚本函数及318个原菜单函数逐字节保留。游戏画面尚未验证。

用户测试：重启游戏后，在变身状态打开变换页，开启皮肤变色，将覆盖强度设为255并选择明显颜色，确认后关闭MCM。应先有保存提示，再看到刷新；无法应用时应显示中文原因。关闭皮肤变色并退出菜单后应恢复原色。
