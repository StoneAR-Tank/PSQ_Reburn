# 换装流程优化：单次计划与事件合并（2026-11-01）

基于PSQ-Reburn-v0.27内部修订44，本次为修订45。仅修改PSQ的主脚本和玩家别名脚本，不改独立服装、NFF、Body Change NG、WingFlight、OSYRN、TRX或UBE，不新增DLL/ESP。

- 变身保存原装备后，按本次操作ID、读档代次和种族建立一次换装计划，缓存要穿的去重部件、需要手动脱下的附加装备。脱衣与穿衣复用计划；失效时重新建立，结束时清空。原始装备清单仍完整保留，用于退出与异常恢复。
- 已与将要穿上的装备直接占用同一槽位的附加装备，由原有EquipItem换装动作排开，省掉前置UnequipItem调用。须提前卸下的帽子、头部物品，以及没有直接槽位冲突但必须清理的额外轻/重甲，仍保留原规则。珠宝、GT Softbody和UBE原生保护不放宽；不再添加不存在的角/翅膀。
- 六部件穿戴阶段统一检查种族与初始化装备账本，单件只做必要的数量、所有权、是否已穿和操作有效性检查。已穿的部件不重复装备；只回收PSQ临时新增的物品。
- PSQ自己的装备／卸装／节点更新回调在外观事务中暂缓衣物、飞行和形变反应，事务结束后通过带操作ID和读档代次的通知合并请求一次形变刷新。现有结束流程继续同步飞行、TRX皮肤与大小。其他模组的装备事件不会被屏蔽；普通手动穿脱装备保留原处理。
- 退出变身及未完成恢复的账本、重试、物品保留逻辑逐字节不变。仍会恢复被引擎槽位替换卸下的原装备，不仅是主动脱下的装备。

验证：旧SexLab与P+2.19均编译通过；530项最终字节码离线检查通过，包括前版Body Change皮肤／UBE回归、32槽位三种护甲类型对照、帽子／护颈／额外护甲、自动槽位替换、珠宝保护、重复部件、已经穿戴、计划过期、事件延迟及结束通知。552个其他主脚本函数和15个其他玩家别名函数逐字节保留，未增加持久脚本字段。

尚未测得游戏内实际加速幅度。重启游戏后用相同地点、相同变身服装分别比较四件套和多配件套装；首次与重复变身分开比较，再测试退出恢复。开启现有装备诊断可在Papyrus日志查看[PSQ-EQUIP] plan（originals/manualStrip/automaticConflicts/selected）与逐件strip/transform耗时。省掉Papyrus调用不等于消除引擎的装备事件、模型加载或物理初始化开销。
